# Plan: Windows 風のタスク結合（アプリごとに 1 ボタン）とサムネイル

## 実装状況: 未着手（設計確定 2026-10-24。着手可）

> 出典: オーナー指示（2026-10-24）「Windows 風 タスクのグルーピング機能を追加する」

## 関連 Plan

- [app-window-grouping.md](app-window-grouping.md) — 既存の「グルーピング」。同じアプリのウィンドウを**隣に並べる**だけで、
  ボタンは 1 ウィンドウ 1 個のまま。本 Plan はその上に、アプリごとに**1 つのボタンへ結合する**表示モードを足す
  （並び順・D&D の仕組みは既存のものを流用する）
- [context-menu-adjustments.md](context-menu-adjustments.md) — 結合ボタンの右クリックメニューは同 Plan の構成を前提にする
- [window-overlap-avoidance.md](window-overlap-avoidance.md) — タスクバーの幅・高さを変えると、重なり回避の基準も変わる
  （タスクバーの矩形は実ウィンドウから取るので、追加の対応は不要の見込み）

## 目的

Windows のタスクバーのように、同じアプリのウィンドウを 1 つのボタンにまとめて、タスクバーを短く・見やすくする。
あわせて、ウィンドウの中身をサムネイルで確かめられるようにする。

## 現状の挙動

- タスクボタンは 1 ウィンドウに 1 個。同じアプリのボタンは隣接して並ぶ（app-window-grouping）
- タスクバーの太さは固定（`display_manager.rs` の `SIDE_WIDTH = 210` / `BOTTOM_HEIGHT = 60`）
- サムネイル表示はない

## 追加する設定

| 設定 | 既定 | 内容 |
|---|---|---|
| タスクを結合する（`combineTasksByApp`） | しない | アプリごとに 1 ボタンにまとめる |
| タイトルを省略する（`combinedHideTitles`） | しない | 結合時のみ有効。ボタンをアイコンだけにする |
| アイコンを大きくする（`combinedLargeIcons`） | しない | 結合時のみ有効 |
| ウィンドウのサムネイルを表示する（`showWindowThumbnails`） | しない | 結合の有無に関係なく有効 |

store.rs（`serde(default)` で既存設定の後方互換を保つ）・types.ts・設定画面に同時に追加する。
結合時のみの 2 項目は、結合がオフのとき設定画面で無効表示にする。

## 変更内容（フェーズ）

### フェーズ 1: 結合表示

- **対象**: `src-renderer/src/utils.ts`（グループ化の純関数）、`pages/index.vue`、新コンポーネント（結合ボタン）
- アプリ（`kCGWindowOwnerName`）ごとに 1 ボタン。表示はアイコン＋タイトル＋ウィンドウ数のバッジ
  - タイトル: 直近にアクティブだったウィンドウのタイトル（取れなければアプリ名）
- クリック: ウィンドウが 1 つならそのウィンドウをアクティブにする。複数なら、ウィンドウ一覧のポップアップを出し、選んだウィンドウをアクティブにする
- headers / footers（ピン留め）・D&D による並び替えは、結合ボタン単位で既存の仕組みを使う
- 結合ボタンの右クリック: [context-menu-adjustments.md](context-menu-adjustments.md) の構成で、「閉じる」を「（アプリ名）をすべて閉じる」に置き換える（設計判断 3）

### フェーズ 2: タスクバーの大きさの切り替え

- **対象**: `display_manager.rs`（`taskbar_bounds` を設定に応じた太さにする）、設定変更時の再配置（`apply_layout` と同じ経路）
- 推奨値（実機で見て調整する。設計判断 4）:

| 状態 | 縦（left / right）の幅 | 横（bottom）の高さ |
|---|---|---|
| 結合しない（現状） | 210 | 60 |
| 結合する・タイトルあり | 160 | 60 |
| 結合する・タイトル省略 | 64 | 48 |
| 結合する・タイトル省略・大きいアイコン | 80 | 60 |

### フェーズ 3: サムネイル

- ボタンにマウスを乗せると、そのウィンドウ（結合ボタンならアプリの全ウィンドウ）のサムネイルを並べたポップアップを出す
- 画像の取得は Rust 側。画面収録の権限は既存の `permission_manager.rs` で取得済み
- 取得は ScreenCaptureKit（`SCScreenshotManager`、macOS 14 以降。設計判断 1）。表示中のみ・低頻度（例: 1 秒）で更新し、直前の画像をキャッシュする
- 実行中の OS が 14 未満なら、設定画面の項目をグレーアウトし、ホバーしてもサムネイルを出さない（OS バージョンはコマンドで返す）

### フェーズ 4: 実機検証

- 3 レイアウト × 結合あり・なし × タイトルあり・なしで表示崩れがない
- 結合ボタンのクリック・ポップアップ・ピン留め・D&D が動く
- サムネイルが出て、表示中の CPU 負荷が許容範囲（アクティビティモニタで計測）

## 設計判断（2026-10-24 オーナー回答で確定）

1. **サムネイルの取得**: ScreenCaptureKit の `SCScreenshotManager` を使う。**macOS 14 以降のみ対応**とし、
   それより前の OS では設定画面の「サムネイルを表示する」をグレーアウトする
   - 根拠: 旧 API の `CGWindowListCreateImage` は macOS 14 で非推奨、macOS 15 の SDK で使用不可（obsoleted）になった。
     `SCScreenshotManager` は macOS 14 で追加された後継 API
   - 注意: `SCScreenshotManager` の画像取得は非同期で、頻繁に呼ぶと遅れが出るという報告がある。
     表示中だけ・低頻度で取得し、直前の画像をキャッシュして先に出す
2. **サムネイルを出すタイミング**: マウスを乗せたとき（Windows と同じ）
3. **結合ボタンの右クリック**: 「閉じる」の代わりに「（アプリ名）をすべて閉じる」を置き、アプリのすべてのウィンドウを閉じる。
   アプリの終了（全て終了）は既存の「強制終了」と役割が重なるため、閉じる操作にそろえた
4. **太さ**: 「フェーズ 2」の表の推奨値で始め、実機で見て微調整する
